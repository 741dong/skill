# 图片复刻为可编辑 PPT · 使用说明

> 把一张设计图（信息图、PPT 截图、AI 生成图）复刻成一页可编辑 PPTX 的技能。  
> 本文是**给人看的说明书**；给 agent 看的操作规程在 [`SKILL.md`](./SKILL.md)，两份不重复。

---

## 一、这是什么

**一句话**：把一张图变成一页 PPT —— 每个字都能改，每个图标都能无损缩放，照片还是照片。

它解决的问题是：你手上有张做好的图（别人发来的截图、AI 生成的示意图、旧 PPT 导出的图片），  
想拿它当模板改一改，却发现**整张图就是一张 JPEG，一个字都动不了**。

常见做法有两种，都不够：

| 做法        | 结果          |
| --------- | ----------- |
| 整张图塞进 PPT | 改不动，放大糊     |
| OCR 全盘重画  | 图标走形、照片毁掉质感 |

本技能走第三条路：**逐元素取舍**。

### 核心思想

一张图里的元素本来就分两类，硬要一种做法通吃必然顾此失彼：

| 元素类型        | 举例                     | 做法             | 为什么                |
| ----------- | ---------------------- | -------------- | ------------------ |
| **规则几何**    | 图标、流程条、箭头、色带、阵列网格、链路连线 | 矢量重绘（真 SVG）    | 有解析式，放大不糊、PPT 里能改色 |
| **照片 / 纹理** | 产品照、实景图、有机插画           | 原切片贴回          | 没有解析式，重绘只会毁掉质感     |
| **文字**      | 所有文字                   | 原生文本框          | 必须能改字              |
| **表格**      | 数据表格                   | 原生表格 `<a:tbl>` | 单元格要能改字、能合并        |

四者互不重叠，各走各的路。

### 效果实测

1600×900 混测图（8 个图形元素 + 3 条文字 + 1 张原生表格），一键复现实测：

| 方案            | 整页 mean  | 整页 >60 差异占比 |
| ------------- | -------- | ----------- |
| 全位图（不做路由）     | 4.59     | 1.39%       |
| **混合路由（本技能）** | **4.90** | **1.32%**   |

矢量化换来的总代价是 **mean +0.31**，而「人眼可见的显著差异」占比反而**低了 0.07pp**。  
原因是：矢量版的误差是平坦区的均匀浅色差，位图版的误差是元素边缘的硬错位 —— **后者人眼更敏感**。

代价集中在哪里、哪些元素反而变好了，见文末「验收怎么读」。

## 三、使用说明

### 3.1 最短上手路径

```bash
PY=<隔离 venv 的 python>
SK=<本技能目录>

# 第一步：准备输入（见 3.3），至少要有原图 + texts.json
# 第二步：一条命令跑完
$PY $SK/scripts/build_deck.py --src 原图.png --work work/

# 产物：work/final/deck-table-vec.pptx
```

跑完之后，**打开 `work/final/` 里的三件东西**：

| 文件                     | 看什么                              |
| ---------------------- | -------------------------------- |
| `deck-table-vec.pptx`  | 最终 PPTX，在 PowerPoint 里打开改字、拖图标试试 |
| `render-pptx-norm.png` | PPTX 真实渲染结果，直接和原图并排比             |
| `compare-render.png`   | 差异热点图，一眼看出哪里没对上                  |

### 3.2 九个阶段

每个阶段的产物都落盘、可查、可单独重跑、可中途人工修改：

| 阶段           | 做什么                    | 产物（`work/` 下）                |
| ------------ | ---------------------- | ---------------------------- |
| `background` | 生成平滑满页底图               | `assets/bg-full.png`         |
| `slice`      | 切图形元素（自动探测）            | `slice-plan.json`、`slices/`  |
| `route`      | **逐元素判定矢量/位图**         | `route.json`                 |
| `vecspec`    | 生成参数化 spec + 细线配置      | `vec-spec.json`              |
| `vector`     | 参数化生成 / 中心线描摹 / 接入手工素材 | `vec-svg/`、`vec-png/`        |
| `layout`     | 组装背景 + 图形 + 文字 + 表格    | `layout.json`                |
| `build`      | 生成 PPTX                | `deck-table-vec.pptx`        |
| `calibrate`  | 闭环校准文字锚点               | `layout-fixed.json`、`calib/` |
| `final`      | 用校准后布局重建 + 逐像素核验       | `final/`                     |

```bash
# 只跑某个阶段 / 某个区间 / 强制覆盖已有骨架
$PY $SK/scripts/build_deck.py --src 原图.png --work work/ --stage route
$PY $SK/scripts/build_deck.py --src 原图.png --work work/ --from route --to build
$PY $SK/scripts/build_deck.py --src 原图.png --work work/ --force
```

### 3.3 你需要手工提供的三样东西

脚本**不做 OCR、不认形状**。以下三项要么由人给，要么由 agent 探测原图后填：

| 输入                 | 内容           | 说明                                                               |
| ------------------ | ------------ | ---------------------------------------------------------------- |
| `work/texts.json`  | 文字清单         | 每条的 `text` / `size_pt` / `ink_box`（或 `anchor_box`）。**这是最主要的体力活** |
| `work/tables.json` | 原生表格（可选）     | 用 `add_tables.py probe` 探网格线给建议值                                 |
| `work/hand/`       | 手工重绘 SVG（可选） | 文件名 = 切片名。整块 `xx.svg`、阵列格子符号 `xx.cell.svg`                       |

`texts.json` 示例：

```jsonc
[
  {"text": "阶段1 | 既有终端定制适配", "size_pt": 30, "bold": true,
   "mode": "left",   "ink_box":    [49, 33, 492, 71]},
  {"text": "站车站", "size_pt": 7.5,
   "mode": "center", "anchor_box": [817, 224, 853, 236]}
]
```

- `mode: "left"` —— 用 `ink_box`（原图墨迹外接框）精确定位。
- `mode: "center"` —— 在 `anchor_box` 内水平居中（胶囊文字、阵列小标签）。

字号**按像素反推，别猜**：用候选字体的 `getbbox` 网格搜索，让墨迹宽高逼近原图。  
换算见 `SKILL.md` 的「字号标定」。

### 3.4 常见操作

**改判定结果**（自动判定错了，要人工覆盖）

```bash
$PY $SK/scripts/route_elements.py --manifest work/slices/manifest.json \
    --ref 原图.png --force-vector 03_photo-a.png --force-raster 05_icon.png
```

或者直接改 `work/route.json` 里的 `decision` / `vector_submode`，把 `needs_review` 置 `false`，  
再重跑后续阶段。终端表会打印「切片 / 判定 / 手法 / 置信 / 依据」，`*` 标记待人工确认的。

**加手工重绘的图标**

把 SVG 放到 `work/hand/<切片名>.svg`，`vector` 阶段会自动接入（不用手工拷贝）。  
格子符号放 `work/hand/<切片名>.cell.svg`。

画之前先记住两条：**画布要等于切片尺寸**（不是 box 尺寸）、**写绝对坐标别用 `scale()`**。  
详见「注意事项」。

**加原生表格**

```bash
# 先探网格线，拿到列宽/行高建议
$PY $SK/scripts/add_tables.py probe --ref 原图.png --box 140,240,1460,700
# 按建议写 work/tables.json，之后重跑 build 阶段会自动叠上
$PY $SK/scripts/build_deck.py --src 原图.png --work work/ --from build
```

写 `tables.json` 时**只写「起始格」**，被合并吃掉的位置不用写占位 —— 脚本用占用表自动跳过并校验。

**校准文字位置**

```bash
$PY $SK/scripts/calibrate_layout.py --layout work/layout.json --ref 原图.png \
    --out-dir work/calib --canvas 1600x900
```

实测 2 轮收敛，收敛后所有文字 |Δ中心| ≤ 1 px。跑过校准的 layout 再跑一次会第 1 轮直接判收敛，  
产物逐字节一致（幂等）。

**跑回归测试**（改过判定逻辑后必做）

```bash
$PY $SK/examples/mixed/unit_classify.py     # 合成 7 类典型元素，检验判定方向没退化
```

比重新切一张真实图快得多。

## 四、注意事项

### 4.1 最容易踩的五个坑

**① 坐标有两种，差一个 `pad`**

这是全链路最容易踩、症状最迷惑的坑：

- **切片**：`box` 外扩 `pad` 之后裁出来的图，尺寸 = `size`
- **core**：切片去掉 `pad` 边框剩下的部分，尺寸 = `box`

`route_elements.py` 的所有量测在 **core** 上做；`param_vectors.py` 画在**切片画布**上。  
所以**凡是绝对坐标都要 `+pad`**（间距类不用加）。

漏加的症状是「**图形整体偏 pad 像素，形状却对**」。

**② 渐变用在描边上，必须写 `userSpaceOnUse`**

SVG 的 `linearGradient` 默认以**路径自己的 bbox** 为单位，而一条水平线的 bbox 高度是 0  
→ 渐变退化 → **整条线不渲染**。实测同一 SVG，默认单位下非透明像素 996，改成  
`userSpaceOnUse` 后 7184。加上 `gradientUnits="userSpaceOnUse"` 就好。

**③ 手工 SVG 的画布要等于切片尺寸**

画布只写 box 尺寸会被等比放大到切片，整体偏 1~2 px。实测某星形图标画布写成 150×150  
（切片是 154×154），该元素 mean 36.4；改成切片口径后降到 3.02。

另外：`transform="scale()"` 会连 `stroke-width` 一起缩放，**用绝对坐标**。

**④ 细线骨架必须重新居中**

`zhang_suen` 细化对偶数宽度的条带只能收敛到其中一行，骨架因此贴在条带一侧，  
而描边以骨架为轴 → 整条偏 `lw/2`。实测 2px 横条整条错位，该元素 mean 31.3；  
重新居中后降到 10.1。脚本已内置 `recenter_on_mask()`，**别关掉它**。

**⑤ 「渲染成功」不等于「画出来了」**

渲染脚本报 OK 只说明 Chromium 没报错。实测正是靠**墨迹覆盖率自检**才抓出「arrow 杆整条丢失」  
（比值 0.17 而渲染自检是 OK）。`build_deck.py` 已内置这道自检（`_check_vec_ink()`）。

再加一道人眼关：`vector_compare.py` 生成并排对比图。前两道都只回答「画出来了没有」，  
回答不了「画得像不像」—— 本项目先后出过「无线信号画成蝴蝶」「显示器底座多色斑」  
「胶囊文字顶满边框」三处**渲染成功但视觉不对**的问题，全靠这张图抓出来。

### 4.2 什么情况下别用这个技能

诚实说边界，别硬上：

| 情况               | 建议                              |
| ---------------- | ------------------------------- |
| 原图就是一张照片，没有可识别结构 | 直接贴图，别复刻                        |
| 文字超过 50 处、都很密集   | `texts.json` 体力成本会超过收益，考虑贴图或分批做 |
| 手写体、艺术字、特殊字体     | 字体匹配不上，字形差异不可消除                 |
| 要求像素级 1:1（如交付印刷） | 位图更准，本技能是「可编辑」优先                |
| 多页文档             | 本技能是**单页**。多页要逐页跑，或另想办法         |

### 4.3 别删错文件

`work/` 目录里的文件分两类：

**依赖**（删了 `layout.json` 会变成引用不存在文件的死配置）：

- `assets/`（背景底图）
- `slices/`（位图切片）
- **`vec-png/`**（矢量元素的**位图占位**，`layout.json` 的 `images[].path` 直接指向它）
- `hand/`（手工重绘 SVG，**不可再生**，删了要重画）
- `vec-svg/`（真矢量，`svg_embed` 取用）

**过程产物**（重跑即得，可安全清理）：

- `calib/`（闭环校准各轮渲染）、`allbitmap/`（对照实验）、`region-measure/`
- `final/` 里的中间版本、`work/` 顶层的中间 PPTX
- `slices/00-overview.png`（切分总览图，**单张就 1.3 MB**）

精简后的示例 = `final/` 三项 + 全部 JSON + 上述依赖目录，约 2.6 MB（原 12 MB）。

### 4.4 环境提醒

- **跨技能路径不能动**：本技能依赖 `../image-subimage-slicer/scripts/` 的三个脚本，  
  两个技能必须保持同级目录（见 2.3）。
- **`--hand` 传不存在的目录会硬报错退出**（这是刻意的）：错误的路径会让手工素材静默回落，  
  表现为「跑通了但 mean 悄悄变高」（实测整页 4.90 → 5.28）。不需要手工重绘就别传这个参数。
- **`--tables` 按当前工作目录解析**（不是按 layout 目录），从别处调用要给绝对路径。
- **`svg_embed.py --verify` 与 `--out` 互斥**，必须先嵌入再单独校验。
- **`layout.json` 里的相对路径按 layout 文件所在目录解析**，不是按当前工作目录。  
  换目录保存时脚本会自动绝对化，手工搬运要留意。

## 五、验收怎么读

### 5.1 四条口径

| 口径              | 阈值                    | 说明                   |
| --------------- | --------------------- | -------------------- |
| **逐元素墨迹框**（主判据） | Δ中心 ≤ 3 px、Δ宽 ≤ 5 px  | 闭环校准会做到 ≤ 1 px，比这条更紧 |
| 逐元素墨迹覆盖率        | ∈ [0.6, 1.6]          | 低于 0.6 基本就是丢了图形      |
| 文字色             | 与原图最暗 3% 中位色偏差 ≤ 5    |                      |
| 逐像素（内容区）        | mean ≤ 12、>60 占比 ≤ 5% | **看之前先读下面的底噪表**      |

### 5.2 逐像素这个数要连着底噪一起解释

先测「固有底噪」——把原图自己平移、模糊一下再比：

| 扰动        | mean | >60 占比 |
| --------- | ---- | ------ |
| 平移 0.5 px | 5.6  | 2.7%   |
| 平移 1.0 px | 11.0 | 6.5%   |
| 高斯模糊 0.6  | 4.3  | 0.1%   |

也就是说「mean ≤ 12」这条**等价于要求全图配准优于 1 像素**。重建类 PPT（不同栅格化器、  
位置按 EMU 取整）在元素级做到 1~2 px 已是极限。

**所以报数时要把底噪表一起给，否则「没达标」是个没有意义的结论。**

另外：核验渲染是 1280×720 再放大到设计基准，**照片这类高频内容在重采样下必然逐像素不一致**。  
照片区域看 `>60` 占比，不看 mean。

### 5.3 逐元素看，别只看整页

整页一个 mean 说明不了问题 —— 照片是高水位、矢量是低水位，混在一起看不出毛病。  
实测逐元素结果（正 = 矢量版更差）：

| 切片          | 手法     | 混合路由     | 全位图      | 差额        |
| ----------- | ------ | -------- | -------- | --------- |
| 03_photo-a  | raster | 20.72    | 20.72    | 0         |
| 06_photo-b  | raster | 15.86    | 15.86    | 0         |
| 08_band     | param  | 10.34    | 0.53     | +9.80     |
| 07_thinline | trace  | 10.10    | 9.96     | +0.14     |
| 01_chip     | param  | 9.31     | 9.70     | **−0.39** |
| 04_grid     | param  | 7.40     | 2.85     | +4.55     |
| 02_arrow    | param  | 3.76     | 2.59     | +1.17     |
| 05_icon     | hand   | 3.02     | 2.65     | +0.37     |
| **整页**      |        | **4.90** | **4.59** | **+0.31** |

读法：

- **`band` 的 +9.80 全是平坦区色差**（`>60` 为 0.00%）—— 参数化的三停渐变复刻不出原图的  
  连续渐变，属可接受；想压就多加几个渐变 stop，不改也不影响观感。
- **`grid` 的 +4.55** 来自「格子符号是手绘的一次近似」，`>60` 落在符号内部笔画边缘。
- **`chip` 是唯一优于全位图的**（−0.39）：矢量重绘 + 闭环校准后，胶囊的描边/圆角  
  反而比原切片的抗锯齿边缘更贴合真实几何。
- **照片两项两边完全一致** —— 路由没动它们，符合预期。

### 5.4 差异怎么归因

把逐像素差按「边缘附近」与「平坦区」拆开看。实测一张 1672×941 信息图：  
**94% 的误差来自边缘区，平坦区几乎为 0**。

- **平坦区差 > 3** → 填充色/描边没测准，改颜色是**最便宜**的收益。
- **平坦区已经很小** → 继续压指标只能靠文字位置与字号，**别再去调面板配色**。
- **差异集中在文字区域** → 字形差异（原图字体 ≠ 你的字体），不可消除；  
  只要宽度和中心对上了就算合格。


- **差异出现在图形/背景区域** → 真问题（素材没对齐、底图有污染、几何没测准）。

## 附：这个技能的来历

本技能由 `image-to-editable-pptx` 与 `image-to-vector-pptx` 于 2026-09-29 合并而成：

- 前者提供骨架（切分、布局、原生文本框、闭环校准、逐像素核验）。
- 后者提供矢量链路（参数化生成器 `param_vectors.py`、中心线描摹 `trace_lines.py`、  
  SVG 嵌入 `svg_embed.py`）。
- 合并的关键是**逐元素路由**：原先两个技能各做各的（一个全位图、一个全矢量），  
  现在由 `route_elements.py` 逐元素判定，取长补短。

旧技能 `image-to-vector-pptx` 目录**保留但已标记废弃**，其中的 `scripts/` 副本不再维护 ——  
有需要请用本技能，不要改旧副本。
